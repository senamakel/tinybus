# Changelog

## 0.3.3

### Fixed

- Publish a stream's completion or truncation verdict before closing its reader
  channel, so a reader that has drained the payload observes the correct end.

## 0.3.2

### Added

- `ModuleClient::bind` returns a private ordinary client pinned to the serving
  peer for root calls, streamed uploads, and held object paths. It supports
  linked modules and fixtures without making an artifact-attestation claim.

### Fixed

- Ordinary bindings preserve the selected proxy's deadline for owner lookup
  and later calls unless the client supplies an explicit override.

## 0.3.1

### Added

- `ModuleRuntime::lease` owns reservation activation on the dedicated runtime and
  returns a cloneable `RuntimeLease` with a shared acknowledged-stop worker.
- `RuntimeLeaseDriver` and `StopOutcome` expose a protocol-neutral lifecycle
  contract on the slim build; only proven-settled failures are retried.
- `RuntimeLeaseDriver::start` returns `StartOutcome` to distinguish acknowledged
  start, a proven-settled failure, and an uncertain remote operation.
- `ModuleClient::bind_attested` returns a client pinned to the proven unique
  peer, including for later calls and held object paths.
- Unacknowledged and faulted cleanup retains the exact callback registration
  until STOP acknowledgement.

### Fixed

- An uncertain START keeps its reservation, object, and callback registration
  owned until an authoritative settlement; it never triggers an overlapping STOP.
- Closing a linked module connection wakes an idle receive without requiring
  another inbound frame, drains queued frames, and refuses sends after close.

## 0.3.0

### Breaking changes

- `RuntimeSetup` now receives the `ModuleHost` alongside its connection, so
  runtime setup can install callbacks without a second process-global slot.
- `LinkedModule` carries an optional Rust-only setup initializer generated by
  `module_export_static!`; struct literals must provide `init_with_setup`.

### Added

- `ModuleHost::attach_linked_with_setup` replaces one linked export's default
  setup with state captured for that admitted instance and waits for readiness.
- `ModuleHost::module_for_sender` resolves broker-assigned unique peers to exact
  admitted `ModuleId`s without a broker lookup.
- `ModuleRuntime::serve_host_object` returns a drop guard for host object and
  name ownership, with cleanup on the module runtime.

### Fixed

- Host object guards remove only their own interface registration and preserve
  names that were already owned before the first guard.
- Canceling or timing out linked setup revokes its pending module admission.
- Module sender identity now requires an exact canonical manifest/descriptor
  match rather than a sanitized display-name match.

## 0.2.2

### Added

- `ModuleClient::call_with_stream` and `call_with_stream_detailed` upload
  payloads through the module's validated proxy; the detailed form preserves
  untrusted remote wire failures while keeping renderings and reports redacted.
- `ModuleObjectClient::call_detailed` retains exact remote method failure
  details for held objects while keeping its sanitized call wrapper.

### Fixed

- A streamed method follows the unique peer that accepted `Open`, so a
  well-known-name handover cannot split its method from its payload.
- A refused protocol frame reports as a transport failure rather than as a
  module execution fault.

## 0.2.1

### Added

- `ModuleClient::call_attested_detailed` retains remote method failure fields
  for product adapters while keeping renderings and failure reports redacted.

## 0.2.0

### Breaking changes

- Module search paths are now opt-in. Hosts that need discovery must configure
  `SearchPathConfig` with their own environment variable and app directory;
  TinyBus no longer assumes OpenHuman's `OPENHUMAN_MODULE_PATH` or data paths.
- `ModuleHost::search_paths` is now an instance method and
  `ResolverInputs` carries optional search-path configuration and a linked
  registry. Update resolver construction to pass a `LinkedRegistry` (usually
  `LinkedRegistry::global()`) and the host's `SearchPathConfig`, if any.

### Added

- `UnloadedAccess` provides registry-backed client access for builds without
  the dynamic module loader.
- Hosts can set a bundled release directory and resolve it using an explicitly
  named environment variable.
